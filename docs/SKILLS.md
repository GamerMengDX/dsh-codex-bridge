# 两个技能与开发流程

**简体中文** | [English](SKILLS.en.md) · [安装使用](USAGE.md) · [角色配置](ROLES.md)

本项目是DeepSeek Harness与Codex之间的专用桥接插件。两个Skill负责不同层次的指导，桥接代码负责实际执行与状态处理。

| 组件 | 解决的问题 |
| --- | --- |
| `multi-agent-development` | 什么时候需要设计、怎样交接、谁验收、失败怎样升级 |
| `dsh-bridge` | 怎样调用DSH、字段是什么意思、怎样理解报告与异常状态 |
| MCP / CLI与执行器 | 输入规范化、启动任务、目录与会话绑定、超时取消、结果检查和轨迹 |

## 按任务复杂度裁剪

| 类别 | 判定 | 流程 |
| --- | --- | --- |
| A | 文案、样式、明确局部修复 | 主控直接处理或先只读定位，不调用设计角色 |
| B | 已有设计，不改变接口、数据模型或模块边界 | 读设计 → DSH实现 → 主控验收 |
| C | 新项目/模块、接口或数据结构变化 | 设计角色 → 用户确认 → DSH实现 → 主控验收 |
| D | 认证、权限、支付、迁移、并发一致性等高风险 | 设计与风险评估 → 用户确认风险和回滚 → 分步实施与加强验收 |

四个角色是主控、设计者、执行者、评审者；评审默认由同一主控承担。这里的独立验收是独立于DSH的实现自述，不代表另一个评审模型或无偏结论。

## 文件交接与任务状态

业务项目保存：`PROJECT_DESIGN.md`（当前设计）、`DECISIONS.md`（决策历史）、`TASKS/`（任务单）。工具位于桥接仓库，不需要把其业务实现复制到每个项目。

使用`task-doc.mjs new`生成任务单，填写实际范围、允许修改、禁止修改和可执行验收条件，再用`set-state`推进合法状态。元信息字段名是`status`；CLI中的目标状态参数是`--state`。

常见路径是`requirements → designing → design_review → ready_for_implementation → implementing → reviewing → passed → delivered`；设计内任务可以从需求直接进入待实现。失败进入修复或重设计路径；缺少条件时标记阻塞。

任务检查器只检查元信息、状态取值及必要标题。即使文档结构合格，也不能证明验收条件已完成。主控需要保存实际命令、退出结果和差异审阅依据。

## 自包含的DSH任务

| 输入字段 | 应写什么 |
| --- | --- |
| `goal` | 要交付的具体结果 |
| `cwd` | 此次任务的明确项目目录 |
| `files` | 相关文件或目录，路径可含逗号 |
| `mode` | 默认`analyze`；用户授权实现后才用`edit` |
| `context` | 已确认设计、上轮结论及DSH无法推断的背景 |
| `constraints` | 允许/禁止范围和其他硬限制 |
| `acceptance` | 可观察或可执行的验收条件 |
| `session` | 同一阶段续接标签；独立任务省略 |
| `timeout_s` | 本轮执行时限 |

DSH不会继承主控的对话。相关历史可通过其自己的会话续接，但需要重新核对外部文件是否变化。复用历史不是免费上下文，也不等于事务性断点恢复。

## 报告字段及验证

| 现有中文标题 | 含义 |
| --- | --- |
| `任务状态` | 成功、部分完成或失败的自述 |
| `结果摘要` | 主要结论 |
| `交付内容` | 实际改动或分析产物 |
| `发现问题` | 可定位的问题与触发条件 |
| `验证情况` | 实际检查、证据和未验证项 |
| `未解决事项` | 风险、缺口及待决事项 |
| `建议动作` | 可执行的下一步 |

桥接另外区分`execution`（执行状态）、`result`（报告结论）、`contractOk`（格式完整性）、`warnings`（警告）。必须一起看；格式合格和进程退出都不代表任务真实通过。

主控检查实际diff、关键实现、可复现验收、设计一致性、回归和可观察副作用。普通实现问题原则上最多两轮有证据的修复；没有进展或指向设计缺陷时升级诊断。用户确认与修复预算主要靠主控遵守流程，不是不可绕过的审批服务。

## 权限与异常边界

- DSH工具在`analyze`下使用只读文件策略；桥接自身仍写运行状态。文件只读不等于禁止网络或没有一切副作用。
- `edit`的workspace-write实际包含工作区及系统临时位置；业务改动仍须在授权范围。严格cwd-only不是本版提供的保证。
- 设计者只读是角色指令，不是独立的系统隔离。
- 当前MCP入口统一排队；进程内会话车道不代表跨进程互斥或完整并行工作区管理。
- `execution_unknown`时，先确认旧任务结束，再考虑恢复；更换标签不自动解决同目录内尚在运行的写入。

## 双语范围

本指南解释现有Skill与报告的中文标题。运行时操作指令、生成任务的必要标题和报告契约保持原样，以免改变模型交接与格式检查。英文用户可以填写英文目标与验收条件，保留工具生成的必要字段和标题。

# 桥接架构与边界

**简体中文** | [English](ARCHITECTURE.en.md) · [技能流程](SKILLS.md)

## 调用路径

Codex通过`server.mjs`的MCP工具或`dsh-task.mjs`的CLI提交任务。两者使用`lib/protocol.mjs`规范化输入和检查报告，交给`lib/runner.mjs`执行。无会话标签时运行一次性headless进程；有标签时通过`lib/host.mjs`续接DSH web host会话。

项目不替代DSH的工具系统，不把它改造成通用Agent后端。Codex设计角色和主控验收是其上的工作流分工。

## 模块职责

| 模块 | 负责什么 |
| --- | --- |
| `protocol` | 字段规范化、输入长度/类型限制、任务提示词和报告格式检查 |
| `runner` | 后端选择、一次性输出捕获、进程组超时处理、统一结果和轨迹关联 |
| `host` | 持久host、事件与轮次关联、取消请求和完成信号 |
| `session-lane` | 同一进程内按session串行，状态未知时拒绝继续 |
| `registry` | 会话标签和目录绑定、注册表保存；不是跨进程的完整事务系统 |
| `trace` | task/session关联和有限元数据；不保存完整报告正文 |
| `workflow` / `task-doc` | 任务分类与状态辅助、任务文档结构检查 |
| 安装模块 | 源码路径发现、受管配置字段、规则标记、备份与卸载记录 |

## 状态不能混为一谈

`execution`记录执行生命周期；`result`来自DSH的报告自述；`contractOk`记录结构是否完整；`warnings`保存缺段、缺证据和异常提示。它们的任意单项都不等于主控验收通过。

取消请求被发出不代表已经中止。续接后端等待轮次结束等信号；不能确认时返回`execution_unknown`并在本进程中标记会话不确定。恢复前需核对实际任务是否结束及文件状态。

## 写入和网络

文件策略由DSH及平台执行。`analyze`任务工具只读；`edit`使用workspace-write，包含工作区和系统临时位置。业务写入仍应遵守用户给定范围。文件策略不等于网络隔离，也不能证明从未发生目录外副作用。

桥接本身需要运行目录、注册表和轨迹；设计角色的只读则主要靠指令和审阅。安装记录、运行home、会话、凭据和本机完整审阅材料不进入公开发行树。

## 安装配置

安装器只维护插件负责的文件和配置。TOML扫描识别注释、引号键、多行字符串及容器边界，再补丁管理字段；不整体重排用户配置。不支持的复杂目标表示会拒绝修改。

卸载依据记录、内容哈希与原内容备份。标记损毁、记录缺失、备份缺失或用户编辑时保留冲突。处理一个组件不会丢弃另一个组件恢复所需的记录。

## 当前限制

- MCP入口全局排队；进程内车道不是跨进程互斥或并行工作区管理。
- DSH历史续接不是事务性工作流checkpoint。
- 一次性输出与续接输出的限额、截断标记处理并不完全相同。
- 格式检查与文档结构检查不验证实现事实；主控仍要独立验收。
- 运行时必要中文字段保持原样，双语文档没有改变任务协议。

v2.2.4仅补充文档、解释注释和发行元数据。执行语义通过JavaScript语法树与shell非注释内容对照验证。
